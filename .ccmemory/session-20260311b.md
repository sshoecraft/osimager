### Proxmox un-template procedure (via SSH)
1. `qm set <vmid> --name <name> --delete template`
2. `chattr -i /var/lib/vz/images/<vmid>/base-<vmid>-disk-0.raw`
3. `mv base-<vmid>-disk-0.raw vm-<vmid>-disk-0.raw`
4. `sed -i 's/base-<vmid>-disk-0/vm-<vmid>-disk-0/' /etc/pve/qemu-server/<vmid>.conf`
- This is what the post-build script should do — SSH to node, not API calls

### qemu.json
- **Added `platform_defs: { "firmware": "bios" }`** — same as Proxmox, forces SeaBIOS
- **firmware field set to empty string** — BIOS is default, no OVMF needed
- QEMU builds were failing with "could not load PC BIOS 'efi'" before this fix

### core.py
- **install_path fixed** — changed from `base_path + /install` (source tree) to `user_dir + /install` (~/.config/osimager/install)

### ISO URL fixes (specs)
- **AlmaLinux**: `vault.almalinux.org` → `repo.almalinux.org/almalinux` for current versions (8.10, 9.7, 10.1); older versions (8.3-8.9, 9.0-9.6, 10.0) set to local-only (ISOs removed from mirrors)
- **Rocky Linux**: `download.rockylinux.org` → `dl.rockylinux.org`; moved arch_specific URLs into version_specific to fix merging (top-level arch_specific overrides version_specific arch_specific — known bug); 8.x uses dvd1.iso, 9.x uses dvd.iso; 9.7 is at /pub/ not /vault/
- **Ubuntu**: 24.04.2 aarch64 → `old-releases.ubuntu.com` (superseded point release)
- **Proxmox VE**: 3.4, 4.4 set to local-only (ISOs removed from enterprise server)

### Spec merging bug identified
- **Top-level `arch_specific` overrides `version_specific` `arch_specific`** — this means you can't use top-level arch_specific as a default and override per-version. Workaround: put all arch_specific URLs in version_specific sections. Rocky and Alma specs restructured accordingly.

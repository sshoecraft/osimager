## Changes

### Two-Layer Data Resolution (v1.7.0)
- Engine separated from data — `osimager` (engine) and `osimager-data` (baseline data) are separate pip packages
- `osimager-data` is a separate GitHub repo, optional dependency
- User overrides in `~/.config/osimager/` for specs, platforms, files, scripts
- `osimager_data` package provides baseline (read-only), detected via `import osimager_data`
- Ansible infrastructure (config.yml, ansible.cfg, tasks/) locked to osimager-data package
- `resolve_data_path(*parts)` and `resolve_data_files(subdir, pattern)` methods in core.py
- All 14 `get_path("data_dir")` call sites migrated to two-layer resolution
- `data_dir` removed from `save_keys` (no longer persisted to config.json)
- Packer CWD uses `system_data_dir` (osimager-data package dir)

### Venv Hoisting Fix
- `load_specific()` now hoists scalar fields (e.g. `venv`) from matched `*_specific` entries onto parent data
- Without this fix, `venv` in `version_specific` was silently dropped and Ansible version requirements were ignored
- RHEL 2-6 specs require `venv: "2.10"` (ansible-core 2.10) — RHEL 6 has Python 2.6 incompatible with modern Ansible

### constants.py Removed
- Was AI-generated boilerplate with unused uppercase constants
- Only 3 values were referenced: `OSIMAGER_VERSION`, `EXIT_SUCCESS`, `EXIT_GENERAL_ERROR`
- Moved to core.py as `OSIMAGER_VERSION`, `EXIT_SUCCESS`, `EXIT_ERROR`

### XDG Paths
- `user_dir`: `$XDG_CONFIG_HOME/osimager` (default `~/.config/osimager`)
- `venv_dir`: `$XDG_DATA_HOME/osimager/venvs` (default `~/.local/share/osimager/venvs`)
- `packer_cache_dir`: `$XDG_CACHE_HOME/osimager` (default `~/.cache/osimager`)

### pyproject.toml
- Fixed version reference: `osimager.constants.OSIMAGER_VERSION` → `osimager.core.OSIMAGER_VERSION`
- Removed `[tool.setuptools.package-data]` section (data no longer shipped with engine)
- Package find changed from `osimager*` to `osimager` (exclude osimager_data dev bridge)

### Development Bridge
- `osimager_data/__init__.py` in source tree points DATA_DIR at `osimager/data/` for development
- When osimager-data repo is created and installed, this bridge becomes unnecessary

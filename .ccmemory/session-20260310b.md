# Session 2026-03-10 (continued) - Proxmox Build Fixes

## Changes Made This Session

### core.py
- **`--local-only` no longer persists to config** — runtime-only override now. Only `--set` saves permanently.
- **`--local` alias** added for `--local-only`

### proxmox.json (platform config)
- `boot`: `order=virtio0;ide2;net0` — disk first, then CD, then network. Empty disk falls through to CD on first boot; after install boots from disk.
- `boot_iso.index`: 2 (pinned to ide2)
- `additional_iso_files.index`: 3 (pinned to ide3)
- `cache_mode`: `writeback` on disks — fixed 25+ min installs down to ~5 min (iSCSI to QNAP was bottleneck with `cache=none`)
- `bios`: conditional — `ovmf` if firmware=efi, else `seabios`
- `efi_config`: conditional — storage pool + 4m type if firmware=efi
- `convert_to_template`: false — keeps VMs as VMs, not templates
- `os` field removed from platform — moved to spec level

### Spec Changes
- **linux/spec.json**: Added `platform_specific` for proxmox with `"os": "l26"`
- **windows/spec.json**: Added `platform_specific` for proxmox with `"os": "win11"`
- **freebsd/spec.json**: Added `platform_specific` for proxmox with `"os": "other"`
- **sysvr4/spec.json**: Added `"os": "other"` to existing proxmox platform_specific
- **ssh/spec.json**: `ssh_timeout` back to 25m

### RHEL 9.*/10.* (rhel/spec.json)
- `firmware: efi` moved to **defs** (not config) — platform handles translation
- Removed all Proxmox `platform_specific` firmware overrides — firmware is an OS decision not platform
- **`firmware_specific`** added: EFI gets GRUB2 boot command (`<up>e...Ctrl+X`), BIOS gets isolinux (`<tab>...`)
- `boot_wait`: 45s for EFI, 10s for BIOS (via firmware_specific)
- `firmware` field removed from spec `config` — platforms handle it (QEMU has it in qemu.json, Proxmox uses bios/efi_config)

### ks-part.sh (kickstart partitioning)
- EFI: `bootloader --boot-drive=$DRIVE` (was `--location=mbr` which is wrong for EFI)
- EFI partition created first (before /boot) for proper GPT layout
- `biosboot` partition only on BIOS (not EFI)
- `BOOTFSTYPE` default changed from ext3 to ext4 — ext3 fails on thin-provisioned storage (MXFS)

### proxmox_post.yml
- **Created then REMOVED** — CD eject via Ansible doesn't work because VM boots from CD before Ansible runs. Disk-first boot order solves the problem instead.

### config.json
- `local_only` reset to `false` (was incorrectly persisted by old --local-only bug)

Major refactor session: ansible venv management

- `venv` field replaced with `ansible_version` in all specs — pinned, not "current"
- `ansible.json` in osimager-data defines per-version: python_min, python_max, pkg name, requirements
- mkvenv reads ansible.json via two-layer resolution (user override possible)
- Python 2 venvs need `pyyaml<5.4` prereq (in ansible.json requirements array)
- Python 2 venvs use `virtualenv` (auto-installed), Python 3 uses `venv` module
- `--skip` flag on mkosimage skips all post-install provisioning
- `OSIMAGER_VENV_DIR` and `VENV_DIR` env vars override venv_dir setting
- `osimager/data/` directory removed from engine repo — all data in osimager-data package
- RHEL 6.10 build verified on Proxmox with ansible 2.9 venv

**Why:** Engine should never need code changes for new ansible versions. Data package handles it.
**How to apply:** New ansible version = add row to ansible.json + set ansible_version in specs. No engine changes.

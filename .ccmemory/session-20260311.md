# Session 2026-03-11 - Proxmox BIOS Default, Post-Build Scripts, Repo Fixes

## Changes Made This Session

### core.py
- **`platform_defs` system**: Platform JSON can define `platform_defs` — defs that cannot be overridden by specs. Filtered during `load_data` so firmware_specific still fires correctly with the protected value.
- **`build_id`**: Generated as `packer-<uuid_hex_12>` each run, stored in defs. Used by Proxmox as temp VM name for unique identification.
- **`run_build_script(path)`**: Loads a Python script from data dir, calls `run(osimager)`. Receives full OSImager instance.
- **`pre_build` / `post_build` hooks**: Platform JSON can specify `pre_build` and `post_build` script paths. Pre runs before Packer, post runs after (on success only).
- **Removed `post_build_libvirt()`**: Moved to `scripts/qemu_post_build.py` — no more hardcoded platform logic in core.py.
- **Added imports**: `importlib.util`, `uuid`
- **Duplicate defs bug fix**: RHEL 9.* had two `defs` blocks — second was overwriting first (lost iso_url, cpu_cores, memory, spec_config). Merged into one.

### proxmox.json
- **`platform_defs: { "firmware": "bios" }`** — forces SeaBIOS on Proxmox, specs can't override
- **`post_build: "scripts/proxmox_post_build.py"`** — removes template flag + renames VM via API
- **`vm_name: ">>build_id<<"`** — uses temp unique name during build, renamed in post_build
- **Removed `convert_to_template: false`** — not a valid Packer field (still open PR after 4 years)

### qemu.json
- **`post_build: "scripts/qemu_post_build.py"`** — libvirt XML generation moved from core.py

### New Files
- **`data/scripts/proxmox_post_build.py`**: Authenticates to Proxmox API, finds VM by build_id, removes template flag and renames to actual name in single API call. Uses urllib (no external deps).
- **`data/scripts/qemu_post_build.py`**: Libvirt XML generation + virsh define (moved from core.py `post_build_libvirt`).
- **`data/tasks/AlmaLinux_post.yml`**: Replaces mirrorlist with repo.almalinux.org baseurl for all repos (baseos, appstream, crb, extras, ha, nfv, plus, resilientstorage, rt, sap, saphana + debug/source variants).

### ks-part.sh (kickstart partitioning)
- **biosboot partition always created on BIOS** — removed 2TB disk size check. RHEL 9 uses GPT always, needs biosboot regardless of size.
- **Combined EFI/BIOS checks** into single if/else block (was two separate checks)
- **Kept `--location=mbr`** on BIOS path (not deprecated enough to remove)

### config.yml (Ansible playbook)
- **Added `ansible_distribution` to pre/post include loops** — enables per-distro task files (e.g., AlmaLinux_post.yml)
- **Added `Restore repo directory` handler** — restores /etc/yum.repos.d from backup after build
- **Added `Fix AlmaLinux repos` handler** — chains after restore, replaces mirrorlist with repo.almalinux.org baseurl

### RedHat_pre.yml / local_repo.yml
- **Added repo backup step** before disabling repos — `cp -a /etc/yum.repos.d /etc/yum.repos.d.bak`, notifies Restore handler

### proxmox.md (memory file)
- Created with known Proxmox issues and configuration decisions

## Key Decisions
- BIOS (SeaBIOS) is default for Proxmox — EFI/OVMF breaks on kernel upgrades
- `platform_defs` filtered during load_data (not applied at end) so firmware_specific fires correctly
- Post-build scripts are data-driven (platform JSON), not hardcoded in core.py
- VM uses unique build_id as temp name for unambiguous identification in post-build
- AlmaLinux repos pinned to repo.almalinux.org (mirrorlist picks slow mirrors)
